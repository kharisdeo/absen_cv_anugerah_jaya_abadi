## Explicit 2FA decision record

The source requirement is permissive (“Admin dapat memakai 2FA”) and lists OTP email/WhatsApp or an authenticator. It does not define mandatory coverage, enrollment/recovery, delivery provider, or rollout. Source and schema inspection found no implementation in this working tree. Therefore the 2FA scope is **UNDECIDED**: before production, the product owner and security/operations owner must record whether Admin 2FA is mandatory or optional, approved factor(s), recovery policy, and an accountable provider/operator. No implementation or product-policy change is made by this audit.

## Rollback and incident readiness

- [Database migration runbook](../../runbooks/database-migrations.md) is documentation only; it is not evidence of a staging or production drill. Prisma migrations in this repository do not have an automatic `down` operation. A database rollback must not be improvised; use a reviewed forward-fix or an explicitly approved compatible restore plan.
- DEP-015 already calls for a rollback owner and incident contact. Those named assignments are still missing. Before any release, record primary/backup contacts, escalation channel, decision authority, deployment artifact to restore, data-compatibility constraints, stop/rollback triggers, and a tested recovery procedure.
- No Git commit/push, provider provisioning, deployment, migration, or live database mutation is included in this snapshot.

## Go-live rule

**Controlled internal staging validation is a separate gate from employee pilot or production.** After an owner explicitly approves the account/resources and expected cost, a restricted staging environment with synthetic data may be provisioned to run migrations, browser/device checks, provider integration, E2E, backup, and restore drills. This snapshot does not authorize or perform that provisioning. It also does not authorize employee/customer exposure.

Before inviting employees to a pilot or exposing production, pass the applicable P0 checks, sign the required business/privacy/security decisions, demonstrate PostgreSQL and provider flows end-to-end, meet the real-device pilot thresholds, evidence backup/restore and named rollback/incident ownership, refresh the dependency audit and AUD-25 decision, and record the Admin 2FA scope. If the owner makes 2FA mandatory, implement and test it before the covered Admin accounts are exposed; if optional, record that explicit decision and its residual risk. Local test success is necessary evidence for its tested slice only; it does not satisfy external gates.
